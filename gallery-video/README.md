# 갤러리에서 직접 찾기 — 폰 화면 목업

발표 01장(Problem)에 넣을 10초짜리 폰 화면이다. 서비스 없이 사진첩에서 직접 찾으면 어떻게 되는지를 보여 준다.
찾는 사진은 데모 질의와 같은 "미셸 들라크루아 전시 보고 나서 갔던 카페 사진"(2024년 1월 13일)이다.

| 시간 | 화면 |
|---|---|
| 0 ~ 2.5초 | 갤러리 검색에 "들라크루아 전시"를 친다. 검색 결과가 없다 |
| 2.5 ~ 6.5초 | 사진을 넘긴다. 스크롤 손잡이를 끌어 2023년까지 갔다가 2024년 3월로 돌아온다 |
| 6.5 ~ 7.9초 | 3월 16일의 카페 사진을 열어 본다. 그 카페가 아니다 |
| 7.9 ~ 10초 | 다시 넘긴다. 찾던 1월 13일이 8.8초쯤 화면을 스쳐 지나가지만 멈추지 않는다 |

끝과 처음이 이어져 계속 반복된다.

## 파일

| `../AI_Dictionary_hackathon_B_new_slide.html` | B안. 01장 바로 뒤에 장표를 하나 더 넣었다. 왼쪽 단계 목록이 폰 화면을 따라 켜진다 |

한쪽을 고르면 나머지 파일은 지우면 된다. B안의 제목과 단계 문구는 초안이다.

## 여는 방법

HTML 세 개는 사진 · 글꼴 · 스크립트가 파일 안에 다 들어 있다. 인터넷이나 다른 파일 없이 그 파일 하나만 있으면 열린다.

1. 저장소를 받는다. `git clone` 또는 GitHub의 **Code ▸ Download ZIP**. 파일 하나만 받으려면 그 파일 화면의 **Download raw file** 버튼을 쓴다.
2. 받은 HTML을 브라우저에서 연다.
3. A안은 → 키를 한 번, B안은 두 번 누르면 폰 화면이 나온다. 주소 끝에 `#2`(A안), `#3`(B안)을 붙여도 된다.

GitHub 웹 화면에서는 HTML이 실행되지 않고 소스로 보인다. 깨진 것이 아니다.
파일 목록에서 우클릭해 "다른 이름으로 링크 저장"을 하면 파일이 아니라 GitHub 페이지가 저장되므로 쓰지 않는다.

## 덱을 고친 뒤 다시 만들기

A · B안은 만든 시점의 덱을 담고 있다. 원본 덱을 고쳐도 따라 바뀌지 않으므로 다시 만든다.

```
pip install pillow
python3 gallery-video/build.py
```

- 01장은 `<i>01</i>`이 든 `<section>`으로 찾는다. 01장의 키커 번호를 바꾸면 `build.py`의 `slide01()`도 고친다.
- B안은 새 장표가 번호를 차지하지 않도록 덱 스크립트의 `const counted = ...` 한 줄을 고쳐 넣는다. 그 줄이 달라지면 `build.py`가 경고를 낸다.
- B안의 제목과 단계 문구는 `src/slide_b.html`에 있다.
- 폰 화면 글꼴은 Noto Sans KR에서 쓰는 글자만 뽑아 `src/.font_cache.json`에 넣어 두었다. 화면에 새 글자를 넣으면 `build.py`가 Google Fonts에서 다시 받는다(이때만 인터넷이 필요하다).

## 장면 고치기

장면은 `src/gallery.js` 한 파일에 있다. 화면 전체를 시간 `t`(0 ~ 10초) 하나로 그리므로 몇 번을 돌려도 같은 화면이 나온다.

- 주소에 `?gpt=6.3`을 붙이면 그 시점에서 멈춘다. 예: `gallery_demo.html?gpt=6.3`
- 손으로 짠 날짜 구간은 `FIXED`, 동작 시각은 `T_GO` · `T_TAP` 같은 상수다.

## 사진 바꾸기

`photos/<분류>/<분류>_<번호>.jpg`를 바꾸고 `build.py`를 다시 돌린다. 분류는 `cafe`, `food`, `city` 같은 폴더 이름이다.

- `gallery.js`의 `FIXED`는 `cafe_004` 같은 파일 이름으로 사진을 지정한다. 그 이름이 없어지면 첫 번째 사진이 대신 들어간다.
- 크게 열어 보는 사진(`cafe_004`)은 `photos/_large/`에 큰 판이 따로 있다.

## 영상으로 뽑기

```
python3 gallery-video/record.py
```

크롬과 ffmpeg이 있어야 한다. `gallery-video/gallery_search_fail.mp4`(1040×1920, 30fps, 10초)가 나온다.
프레임을 찍는 데까지만 확인했다. ffmpeg으로 묶는 단계는 아직 돌려 보지 않았다.

## 확인한 것과 못 한 것

- 파일 하나만 빈 폴더로 옮기고 네트워크를 막은 상태에서도 화면이 같다.
- 윈도우용 git이 줄바꿈을 CRLF로 바꿔도 화면이 같다.
- 1024×768부터 3840×2160까지 폰이 장표 안에 들어오고 글과 겹치지 않는다.
- 크롬 154와 Firefox 157(Linux)에서 확인했다. Safari, Windows, macOS에서는 열어 보지 않았다.
- 폰 화면은 삼성 갤러리를 본떠 그린 것이다. 실제 기기 화면과 대조하지는 않았다.
- 사진이 들어가서 덱 용량이 242KB에서 약 1.6MB로 늘었다.
