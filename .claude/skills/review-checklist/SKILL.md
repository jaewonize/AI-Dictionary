# 리뷰 확인 항목

리뷰 형식·심각도([필수]·[권장]·[참고])·재리뷰와 반복 종료는 AGENTS.md "코드 리뷰 규칙"을 따른다. 아래 항목은 변경과 관련된 것을 모두 확인한다. 스택에 딸린 항목(프레임워크·계층 구조 규칙 등)은 `workspace/`의 스택이 정해지면 더한다.

- 정확성: 경계값, 빈 값·null, 오류 경로, 비동기 순서·경쟁, 끊긴 요청 정리(하위 프로세스 종료, 스트림·연결 해제).
  - 오류를 빈 값이나 성공으로 삼키지 않는가. 예: 불러오기 실패를 "데이터 없음"으로 처리, 취소 실패 무시, 저장에 실패한 사본 버림.
  - 오류 종류가 맞는 상태 코드·메시지로 나가는가.
  - 폴백 경로가 실제로 실행되는가. 예외가 try 밖에서 나면 폴백 대신 기동 자체가 실패한다.
- 비동기 경쟁:
  - 오래 걸리는 작업(모델 호출·색인·파일 처리)은 결과를 시작할 때의 대상에 반영하는가.
  - 늦게 끝난 요청이 더 새 상태를 덮어쓰지 않는가. 마지막 요청만 반영하고, 폐기된 요청은 성공으로 응답하지 않는다.
  - 진행 중 작업과 겹치는 조작을 처리하는가. 예: 저장 중 들어온 변경을 이어서 저장, 취소 완료 전 재시작. 취소가 실패하면 그 전에 바꾼 상태를 되돌리는가.
- 식별자·키:
  - ID로 찾는 곳이 그 ID의 범위(사용자·문서 묶음 등)까지 확인하는가.
  - 서로 다른 값이 같은 키가 되지 않는가. 확인할 것: id와 이름의 네임스페이스 분리, 정규화하거나 자른 뒤의 충돌, 짧은 해시.
- 프로세스·바깥 호출:
  - 하위 프로세스를 그룹째 끝내는가(SIGTERM → 유예 → SIGKILL). 그룹이 사라진 뒤에 결과를 내는가.
  - stdin 쓰기 오류(EPIPE)를 처리하는가.
  - git·HTTP·DB·모델 API 호출에 제한 시간과 취소가 있는가. connect timeout은 쿼리와 잠금 대기에는 적용되지 않는다.
  - 서버 종료 때 새 작업을 거절하고, 정리가 끝난 뒤 종료하는가.
  - POSIX 전용 동작(음수 PID, 심볼릭 링크)이 Windows에서 어떻게 동작하는가.
- 범위: PR 제목·본문과 diff가 일치하는가. 리팩터링과 동작 변경이 섞여 있지 않은가. `workspace/` 밖 파일을 요청 없이 고치지 않았는가.
- 계약: API 요청·응답 모양, 실패 응답 형식, 화면과 서버가 함께 쓰는 타입을 바꿨다면 쓰는 쪽(화면·서버·문서)이 함께 맞춰졌는가.
- 일관성: 같은 규칙(상태 전이·검증 등)을 여러 곳에서 따로 구현하지 않고 한 곳의 규칙을 쓰는가.
- 화면 상태:
  - 요청 중에는 결과를 뒤집는 조작(입력·취소·뒤로·네비게이션·Esc)을 잠그는가.
  - 서버 값을 받기 전에는 편집을 막아, 옛 값으로 덮어쓰지 않게 하는가.
  - 언마운트된 화면의 늦은 완료 콜백이 페이지 상태를 바꾸지 않는가.
  - 숨은 상태(떠난 페이지의 다이얼로그 플래그 등)가 Esc 처리 순서를 가로채지 않는가.
  - 목록·배지·요약을 같은 기준으로 계산하는가. 상태를 정확히 표시하는가(취소를 완료로 표시하지 않음).
  - 목록↔상세를 오갈 때 스크롤 위치와 포커스가 유지되는가.
- 바깥 입력 검증: HTTP body·LLM 출력·외부 이벤트를 배열 원소까지 검사하는가.
  - 확인할 값: null이나 다른 타입, 예약값(`__proto__` 등), 자기 참조·부모 순환, 빈 배열, 원소 안의 줄바꿈, 큰 숫자의 정밀도 손실.
  - 모르는 enum 값과 길이 초과는 기본값으로 바꾸거나 조용히 자르지 말고 거절하는가.
  - ID를 발급할 때 검증 범위 끝에서 실패하지 않는가.
- 보안: 토큰·API 키·`.env*`·개인 설정이 diff에 없는가.
  - `.env*` 파일은 예제라도 추적하지 않는다. 예제 파일 이름은 `env.example`로 한다.
  - 스킬·스크립트가 `.env` 전체를 모델 컨텍스트에 읽어 들이지 않는가. 필요한 줄만 읽어야 한다.
  - 상태를 바꾸는 요청의 Origin을 요청 Host와 비교하는가.
- 테스트: 동작 변경에 맞는 단위 테스트가 있는가. PR 본문 테스트 항목이 실제 실행 결과와 맞는가.
- 문서: 동작·API·환경변수 변경이 docs/ARCHITECTURE.md에 반영됐는가.
  - 문서에 적힌 명령이 그대로 실행되는가.
